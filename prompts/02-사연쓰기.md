# 02 · 사연 쓰기와 진료과 정리

> `00-공통.md`를 먼저 읽는다. **이 기능이 제품의 축이다. 다른 것보다 먼저 만든다.**

## 만드는 것

환자가 자기 말로 증상을 적으면 **진료과 후보**와 **응급 신호**로 정리해 보여 주고, 사연으로 올리는 흐름. 라우트는 `src/app/ask/`.

## 기존 구현을 참조한다 — 다시 만들지 않는다

앞선 PWA(`../MediVU-community/`)에 **이미 돌아가는 판정 로직과 테스트가 있다.** 화면은 버리고 **도메인 로직은 가져온다.**

| 가져올 것 | 무엇인가 |
| --- | --- |
| `src/domain/triage.ts` (51줄) | 증상 문장 → 진료과 후보 + 응급 신호. **순수 함수라 그대로 옮겨진다** |
| `src/data/rules/triageRules.ts` (98줄) | 진료과별 키워드 규칙. `asOf`와 함께 있다 |
| `src/data/rules/questionBank.ts` (263줄) | 문진 문항 |
| `src/domain/triage.test.ts` | **테스트를 함께 가져온다.** 옮긴 뒤 통과하는지 먼저 확인한다 |

**가져오지 않는 것**: `src/features/patient/AskScreen.tsx`(691줄). 화면은 새로 만든다 — 이 재시작의 이유가 그 화면이다.

옮길 때 **로직을 고치지 않는다.** import 경로만 맞춘다. 고치고 싶은 곳이 보이면 옮긴 뒤 별도로 한다.

## 흐름

```
1단계 증상 적기      자유 서술. 빈 화면 공포를 줄이려면 상황 프리셋을 먼저 보여도 된다
   ↓                 (프리셋 → 키워드까지만. 프리셋이 진료과를 확정하면 안 된다)
2단계 정리 확인      진료과 후보 + 응급 신호 + 의사에게 전할 정리문
   ↓
3단계 공개 범위      Q에 올릴지, 특정 의료진에게만 보낼지
```

## 절대 지켜야 하는 출력 경계

**진단명·질병 확률·중증도를 출력하지 않는다.** 2단계 출력은 이 셋으로 한정한다:

1. **진료과 후보** — 순위 없이 나열. 점수·퍼센트를 붙이지 않는다
2. **응급 신호** — 「지금 병원에 가야 하는 신호가 보인다」까지. 병명을 말하지 않는다
3. **의사에게 전할 정리문** — 환자가 쓴 문장을 다듬은 것. 없던 사실을 만들지 않는다

이 경계를 넘는 순간 의료기기 인허가 대상이 된다. 화면 문구도 「가능한 질환」 「의심 증상」 쪽으로 새지 않게 한다.

## 화면 규칙

- **한 화면에 하나의 결정.** 증상·이력·공개 범위를 한 화면에 몰지 않는다
- 입력값은 **뒤로 가기와 앱 종료 후에도 남는다**
- 오류는 제출 시점에 확정한다. 타이핑 중에 빨간 글씨를 띄우지 않는다. 형식 힌트는 실시간
- 제출은 **중복 실행을 시스템이 막는다**
- 2단계 정리문은 **환자가 고칠 수 있어야 한다.** 앱이 쓴 문장을 환자 이름으로 내보내지 않는다
