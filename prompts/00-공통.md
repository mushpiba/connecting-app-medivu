# 공통 — 어떤 기능을 맡든 이것부터 읽는다

> 기능별 프롬프트(`01`~`06`)는 이 파일을 전제로 쓰였다. **이 파일을 먼저 읽고 시작한다.**

## 어디서 무엇을

- 작업 위치: `MediVU/MediVU-app/` — Expo(React Native + TypeScript), expo-router 57, 라우트는 `src/app/`
- **디자인 규칙 정본은 저장소 루트의 `CLAUDE.md`다.** 세션에 자동으로 들어온다.
  조사본 셋이 엇갈린 지점(진행 표시 · 모션 시간 · 확인 대화상자 · 대리 모드 색 · 낙관적 UI 등 8건)은
  **`CLAUDE.md` §4에서 이미 확정했다.** 원본을 다시 읽고 뒤집지 않는다
- 참조 자료는 **저장소 밖**에 있다: `../Connecting-app/`
  - `design-research/Claude/DESIGN_RULES.md` — 규칙 55개 (강도·근거 등급·검증 방법 포함)
  - `design-research/Claude/COMPONENT_AND_STATE_GUIDE.md` — 토큰·컴포넌트·문구 기준
  - `reference-research/Claude/SCREEN_PATTERNS.md` — 탭별 대안 패턴과 규제 충돌 판정
  - `구상1.txt` — 사용자가 그린 화면 구상 (확정 아님)
- 결정 기록: `DECISIONS.md`. **여기와 어긋나게 만들지 말고, 어긋나야 할 이유를 찾으면 그 파일에 적는다.**

## 제품 한 문장

환자가 자기 말로 적은 증상을 **진료과 후보**로 정리해 의사에게 보내고, 모인 답변에서 **볼 의사를 스스로 골라** 대면 예약 또는 비대면 진료까지 잇는 앱. **진단하지 않는다.**

## 절대 만들지 않는 것 셋

나중에 덜어낼 수 없어서 처음부터 없다. 요구가 들어와도 만들지 말고 되묻는다.

1. **평점·후기·가격** — 데이터가 쌓인다. 없애면 약속을 깨는 일이 된다
2. **진단명·질병 확률·중증도** — 넣는 순간 의료기기 인허가 대상이 된다
3. **플랫폼이 만든 의사 목록·정렬** — 의사는 **답변에 붙어서만** 등장한다. 목록이 되는 것은 사용자가 별표한 것과 진료받은 적 있는 곳뿐이다. 정렬은 최신순 하나로 고정하고 그 사실을 화면에 쓴다

의사 프로필에 넣을 수 있는 것: **성명 · 성별 · 면허 종류 · 진료과목 · 소속 기관 명칭·소재지·전화번호.** 그 밖은 넣지 않는다.

## 코드 규칙

- **토큰 이름만 쓴다.** 숫자·색을 화면 코드에 직접 넣지 않는다. 정본은 `src/theme/tokens.ts`
- 이미 있는 것을 다시 만들지 않는다:
  `Screen` `Section` (`components/ui/screen.tsx`) · `AppText` · `ActionButton` · `ListRow` · `EmptyState` · `StatusBadge`
  모자라면 **`components/ui/`에 추가**하고 화면 파일 안에 일회용 컴포넌트를 만들지 않는다
- 모든 인터랙티브 요소: 히트 영역 `size.touchMin`(48) 이상, `accessibilityRole`·`accessibilityState` 부여
- 색 단독으로 의미를 전달하지 않는다. 아이콘 모양이나 글자를 함께 준다
- `allowFontScaling`을 끄지 않는다. OS 글자 크기를 그대로 따른다

## 문구 규칙 — 여기서 가장 많이 틀린다

- **화면 제목 아래에 설명 줄을 두지 않는다.** 섹션 제목과 버튼 라벨이 이미 말하고 있으면 같은 말을 두 번 하는 것이다
- **한 문장 40자 이내, 한 문장에 한 정보**
- 버튼 라벨은 **동사 + 목적어**. `확인` `제출` `완료` `OK` 금지
- 금지어: `죄송합니다` `유효하지 않은` `필수 항목입니다` `오류가 발생했습니다` `앗` `간편하게` `스마트하게` `쉽고 빠르게` `잠시만 기다려 주세요`(단독) `곧` `잠시 후`
- 상태는 **다른 단어**로 구분한다: 저장 / 보내는 중 / 접수됨 / 확정 / 실패. `완료` `처리됨` 같은 뭉뚱그린 말을 쓰지 않는다
- 접수·확정에는 **시각을 붙인다**. 실패에는 **원인과 다음 행동**을 붙인다
- 규제 때문에 반드시 남아야 하는 문구가 있다(정렬 기준 공개 등). 그건 지운다 말고 **줄인다**

## 빈 상태가 기본값이다

출시 초기에는 사연 0건 · 의사 0명 · 진료 이력 0건이다. **모든 목록의 빈 상태를 먼저 만든다.**
빈 상태는 세 요소를 갖는다 — 왜 비어 있는가 / 무엇을 하면 되는가 / 행동 버튼.

## 만들면서 지키는 것

- 진행 중 작업과 입력값은 **뒤로 가기·앱 종료 후에도 남는다**
- 중복 실행은 시스템이 막는다. 버튼 비활성화만으로는 부족하다
- 대리 이용(보호자)은 예외가 아니다. **누구의 정보인지 항상 화면에 있다**
- 되돌리기 어려운 의료 행위에는 확인 대화상자를 둔다. 라벨은 **행동을 반복**한다 — `[○○약국으로 보내기]`

## 서버는 아직 없다

전부 **화면 안의 상태**로 만든다. 데이터는 `src/data/`에 모듈로 두고, 나중에 서버로 갈아끼울 수 있게 **화면이 직접 fetch하지 않는다.**

## 테스트 — 세션이 스스로 쓴다

도메인 로직(순수 함수)을 추가하거나 옮겨오면 **그 세션이 테스트를 함께 쓰고 돌린다.**
러너는 vitest이고 `vitest.config.mts`에 이미 붙어 있다.

- 대상은 `src/**/*.test.ts` — **순수 함수만.** 판정 규칙, 상한 계산, 상태 전이 같은 것
- **React Native 컴포넌트는 테스트하지 않는다.** RN 트랜스폼을 붙이지 않았다. 화면은 웹 미리보기로 눈으로 본다
- 테스트가 없어도 러너는 통과한다(`passWithNoTests`). 첫 테스트가 들어오면 그 줄을 지운다

## 끝내기 전에

```bash
npx tsc --noEmit
npm run test:run
```

린트는 **네가 만지거나 새로 만든 파일에만** 돌린다:

```bash
npx eslint src/app/ask src/components/ui/my-new-thing.tsx
```

`npx eslint .`는 지금 빨갛다. **전부 Expo 템플릿 잔재다**(themed-text, constants/theme,
collapsible 등 — 라우트에서 도달하지 않는 파일 10개). 남의 실패를 네 실패로 세지 마라.
잔재가 정리되면 저장소 전체가 관문이 된다.

`eslint.config.js`는 CLAUDE.md의 규칙 중 **기계로 잡히는 것**을 담고 있다 —
금지어, 무맥락 버튼 라벨, `allowFontScaling={false}`, 색·글자 크기 직접 쓰기,
`accessibilityRole` 없는 Pressable, 화면에서의 직접 `fetch`.
**규칙을 끄려면 왜 껐는지 주석에 남긴다.**

웹 미리보기로 눈으로 확인한다 (모바일 375×812 기준):

```bash
npm run web
```

- 40자 넘는 문장이 남았는지 훑는다
- 빈 상태에서 화면이 말이 되는지 본다
- 커밋은 **한 커밋이 한 가지만** 하게 자르고, 메시지에 **왜**를 적는다
