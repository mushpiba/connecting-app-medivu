# 00 · 기술 탐침 — 화면을 붙이기 전에

> `00-공통.md`를 먼저 읽는다. **이 세션은 화면을 만들지 않는다.**

## 왜 이걸 먼저 하나

`DECISIONS.md`가 스스로 적어 놓았다 — 미해결 #4, *"기술 탐침 미실시. 화면이 붙기 전에 도는지 봐야 한다."*
그런데 순서는 02(사연 쓰기)부터 시작하게 돼 있었다. 그대로 가면 **02~06을 다 만든 뒤에** 스택이 안 되는 걸 알게 된다.

특히 **한국어 음성 전사**는 D-1(React Native 채택)의 근거 그 자체다.
*"이전 PWA를 막았던 벽 — iOS WKWebView에 `SpeechRecognition`이 없다 — 이 여기서 뚫린다."*
**이게 안 뚫리면 스택 결정을 다시 봐야 한다.** 화면 6개를 만든 뒤에 알 일이 아니다.

**P5는 지금 끝나지 않을 수 있다.** 미해결 #1이 그대로다 — 양대 스토어 모두 의료 앱을 개인 개발자 명의로 받지 않는다(Apple 5.1.1(ix) / Google organization + D-U-N-S).
**끝내려 하지 말고 어디까지 되는지만 확인해서 적는다.** 계정 없이 확인할 수 있는 범위와, 계정이 있어야 넘어가는 지점을 나눠서 쓴다.

## 하는 방식

- **버전 문서를 먼저 읽는다.** Expo 57 · RN 0.86 · React 19.2다. 기억에 있는 API를 쓰지 않는다 (`AGENTS.md`)
- 탐침은 **버리는 코드로 한다.** `src/app/`에 화면을 만들지 않는다. 확인이 끝나면 지운다
- 라이브러리를 고르기 전에 **후보 두셋과 고른 이유**를 적는다. 하나만 써 보고 "된다"로 닫지 않는다
- 안 해 본 것을 "될 것이다"로 적지 않는다. **확인한 것과 추정한 것을 나눈다**

## 결과를 어디에 적나

`DECISIONS.md`에 적는다. 항목마다 이 넷을 채운다:

```
무엇을 / 어떤 환경에서(기기·OS·버전) / 실제 결과 / 확인하지 못한 것
```

- **된 것** → `DECISIONS.md`에 결정으로 올리고 미해결 #4에서 뺀다
- **안 된 것** → 무엇이 막았는지와 대안 후보를 적는다. 관련 프롬프트(04 등)의 범위를 줄인다
- **계정 때문에 못 한 것** → 미해결에 남기되 **무엇이 있으면 끝나는지**를 한 줄로 적는다

`DECISIONS.md` D-1의 *"아직 정하지 않은 것"* 네 줄(화상 SDK · 전사 방식 · 서버 · OTA)이 이 세션 뒤에 줄어 있어야 한다.

## 하지 말 것

- **화면 만들기.** 그건 01~06이 한다
- 탐침용으로 넣은 의존성을 `package.json`에 남겨 두기. 쓰기로 정한 것만 남긴다
- 한 번 돌아간 걸로 "된다"고 적기. **어떤 기기·어떤 OS에서**인지 없으면 결과가 아니다
- 막힌 걸 감추고 넘어가기. 막힌 지점이 이 세션의 산출물이다
